# Módulo Plan de Acción Q100

Seguimiento de las **metas prioritarias anuales de la VPAC** (Vicepresidencia de
Asuntos Públicos y Comunicaciones) — Taller "100 días". Reporte para la gerencia
corporativa. Homologa la plataforma externa que estaba en uso
(`planes-de-accion.dinamicaplataforma.com`) dentro del Sistema AM, con estética
Antofagasta Minerals.

## Acceso
- Slug: **`q100`** (JWT `app_metadata.accesos`), validado por RLS con
  `tiene_acceso('q100')`. `es_admin()` bypasea.
- Login vía `shared/js/auth-guard.js` (`window.AUTH_CFG`, `storageKey am_q100_auth`).

## Archivos
```
modules/q100/
├── index.html   estructura: gate de login + shell del dashboard
├── q100.css     estética AMSA (teal/dorado, Barlow)
└── q100.js      carga en vivo (RPC) y render del dashboard
```

## Modelo de datos (schema `q100`, RLS)
Plan anual → **Ciclos (Q, ~100 días)** → **Metas (10)** → **Líneas** →
**Acciones (hitos)** → **Avances por ciclo** (% + comentario). Cada acción tiene
área, criticidad (`critica`/`no_critica`), fecha término. Responsables internos en
`q100.responsables` (aguas abajo del área). Tablas: `areas, usuarios, planes,
ciclos, metas, lineas, acciones, avances, responsables, api_keys, log`.

**Jerarquía:** la vista corporativa muestra el **área** como responsable (rollup),
no las personas internas. Roles `corporativo / area / subgerencia` en
`q100.usuarios` (reglas finas de visibilidad: pendientes de afinar).

## RPCs (public, SECURITY DEFINER, validan `tiene_acceso('q100')`)
- `q100_contexto()` → planes, ciclos, áreas, rol/área del usuario.
- `q100_dashboard(p_ciclo text)` → JSON con `global`, `metas`, `areas`, `matriz`
  (Meta×Área) y `momentum` (vs ciclo anterior). El schema `q100` no se expone por
  PostgREST; toda lectura pasa por estas RPC.
